# Testing

Ferrum uses a layered test strategy:

- crate-level unit and integration tests (`cargo test --workspace --all-targets`)
- lint and formatting gates (`cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`)
- GA4GH conformance and cross-service checks in CI via HelixTest
- Docker demo + TES pilot smoke (`make test-tes`, `make smoke-pilot`)

## Local verification

Before opening a PR, run:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets
```

## Docker demo + pilot stack

After `make up-tes` (real Docker-backed TES):

```bash
make test-tes        # ingest, Crypt4GH encrypt round-trip, WES COMPLETE
make seed-pilot      # optional: BAM, VCF, chr22 ref bundle on MinIO
make smoke-pilot     # full pilot smoke (Crypt4GH, lineage, cohort, CWL, optional germline)
```

On **macOS**, germline TinyGermlineHC may end in `EXECUTOR_ERROR` (nested Docker); smoke exits 0 with a WARN. Linux CI sets `SMOKE_REQUIRE_COMPLETE=1` and requires `COMPLETE`.

Hard-fail germline locally:

```bash
SMOKE_REQUIRE_COMPLETE=1 make smoke-pilot
```

Crypt4GH keys are generated by `ferrum-init` into the `crypt4gh-keys` volume. Use `make down` to keep keys; `make destroy` wipes keys and MinIO data (encrypted blobs become unreadable). See [docs/CRYPT4GH.md](docs/CRYPT4GH.md).

Edge mode integration tests and offline E2E:

```bash
cargo test -p ferrum-embed
sh deploy/scripts/ci-edge-demo-e2e.sh
```

See [docs/AFRICA-DEPLOYMENT.md](docs/AFRICA-DEPLOYMENT.md) for the one-command user path (`ferrum demo start --edge`).

## Contribution expectation

Behavioral changes should include tests. If tests are not practical, document the rationale in the PR.
